# 01. 项目目标与范围

## 1. 产品定位

构建一个面向业务数据录入、查看和轻量分析的 Web 表格。体验参考 Google Sheets/Excel 的常用交互，但不追求首期完整复刻 Excel。

### 目标用户场景

- 大量业务行数据的查看、编辑和批量粘贴。
- 多列文本、数字、日期和简单公式。
- 选择区域、复制粘贴、填充、格式设置。
- 冻结行列、调整列宽行高、合并单元格。
- 保存、恢复、CSV/XLSX 导入导出。
- 未来可扩展多人协作和权限管理。

## 2. 容量目标与正确理解

Excel 工作表的坐标上限可作为兼容性目标：1,048,576 行、16,384 列（A 到 XFD）。这不是要求系统在浏览器内存中创建全部单元格。

必须区分以下指标：

| 指标 | 含义 | 首期策略 |
|---|---|---|
| 坐标上限 | 用户可以滚动/跳转到的逻辑位置 | 设计上支持，逐步验证浏览器滚动高度限制 |
| 实际非空单元格数 | 有数据或公式的单元格数量 | 通过压测定义支持级别 |
| 单次视口单元格数 | 当前可见区域内的单元格 | 受视口大小和缓冲区控制 |
| 单次请求数据量 | 后端返回的块/行段数据 | 分块分页，设置硬上限 |
| 单次操作范围 | 一次粘贴、格式或删除覆盖的区域 | 设定最大范围并支持异步任务 |

不得宣传“支持百万行”而不明确是逻辑坐标、数据存储，还是可交互性能指标。

## 3. 首期明确不做

- 不在内存中维护完整行列二维数组。
- 不给每个单元格创建 Vue 组件或 DOM 节点。
- 不以 MySQL 每个空单元格一行的方式建模。
- 不实现全部 Excel 函数、宏、数据透视表和复杂图表。
- 不将多人实时协作作为第一阶段依赖。
- 不允许客户端直接决定工作簿权限或持久化版本。

## 4. MVP 验收条件

- 可以创建工作簿和工作表。
- 网格滚动、选区、单元格编辑稳定。
- 支持键盘导航、复制粘贴和批量填入。
- 支持基本单元格格式和行列尺寸。
- 保存/重新打开后数据一致。
- 有明确的错误反馈、版本冲突提示和恢复路径。
- 自动化测试覆盖坐标映射、稀疏存储、命令和持久化。
- 有可重复执行的性能基准和内存测试。

## 5. 非功能要求

- 关键编辑操作有可观测的耗时指标。
- API 有统一错误结构、请求追踪 ID 和结构化日志。
- 所有写操作都经过身份认证、资源级授权、参数校验。
- 开发阶段数据库 schema 与数据由 AI 助手接手管理，可用 Navicat 或命令行；变更前备份，变更后核对结构并同步文档；删除操作需 Aistor 授权；不要求迁移框架或版本登记。
- 日志和错误信息不输出 SQL 参数中的敏感业务数据。
