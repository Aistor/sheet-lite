# 09. 测试、质量门禁与性能验收

## 1. 测试分层

### 前端单元测试

- 坐标解析：A1、Z1、AA1、XFD1048576 与 0-based 坐标转换。
- 稀疏存储：设置、读取、删除、空字符串、公式空字符串。
- 布局：行列尺寸、隐藏行列、冻结窗格和滚动映射。
- 选区：鼠标命中、Shift 扩展、键盘导航。
- 命令：执行、撤销、重做、失败回滚。
- 剪贴板：TSV 边界、单元格换行、HTML 降级和尺寸限制。
- 公式适配：输入、计算结果、错误、依赖更新和释放。

### 后端测试

- Service 业务规则和权限校验。
- Mapper SQL 集成测试，使用真实 MySQL，而不只依赖 H2。
- 批量写入事务原子性。
- revision 冲突和 operationId 幂等性。
- 范围校验、请求体限制、非法坐标和恶意输入。
- 数据库变更检查：备份可恢复、表/索引/注释与文档一致、关键查询可执行。

### 浏览器端到端验收（人工执行）

项目不使用 Playwright，也不默认引入其他浏览器自动化框架。Vitest 负责单元测试及适合在测试环境中运行的模块集成测试；需要真实浏览器、操作系统或用户权限的流程，按人工验收清单逐项执行并记录结果。

- 创建工作簿、输入、复制粘贴、保存、刷新后恢复。
- 长文本、输入法 composition 事件、快捷键、滚动到远端单元格。
- 网络断开、保存失败、revision 冲突提示。
- 浏览器缩放、不同 DPR、目标浏览器兼容性和系统剪贴板权限。

建议将清单维护在 `frontend/tests/manual/`，每条用例记录前置条件、操作步骤、预期结果、实际结果、浏览器/操作系统版本和执行日期。对于可独立验证的业务逻辑，应优先用 Vitest 自动化，避免将人工验收当作单元测试的替代品。

## 2. 性能测试数据集

至少建立以下数据集：
1. 极稀疏：大量逻辑行列、少量随机非空单元格。
2. 连续业务数据：几十万行、几十列，常见文本/数字。
3. 密集区域：大量单元格集中在可见块附近。
4. 长文本：文本长度分布真实。
5. 样式密集：大量不同样式和边框。
6. 公式密集：简单公式、链式依赖、大范围聚合。

测试时记录数据生成方式、硬件、浏览器、JDK、MySQL 版本和配置，保证结果可复现。

## 3. 必测指标

| 类别 | 指标 |
|---|---|
| 渲染 | 初次打开耗时、滚动帧率、可见区域重绘耗时 |
| 交互 | 点击命中、键盘移动、编辑提交延迟 |
| 粘贴 | 1×1、100×20、1000×20 等批量场景耗时 |
| 网络 | 块读取延迟、响应体大小、写请求延迟 |
| 数据库 | SQL 数量、慢查询、锁等待、批量写入吞吐 |
| 内存 | 浏览器峰值内存、长期滚动后的增长、公式引擎内存 |
| 正确性 | 保存/加载一致性、revision 单调性、撤销恢复一致性 |

## 4. 建议初始性能目标

这些是待验证的工程目标，不是承诺值；在目标设备上建立基准后再调整。

- 常见视口滚动不出现明显卡顿；目标设备上争取维持接近 60 FPS。
- 视口块读取返回大小受控，避免一次加载整张表。
- 普通单格编辑在网络稳定时快速确认；保存状态要可见。
- 批量粘贴超过同步操作阈值时提示或进入异步路径。
- 空白工作表打开成本不随逻辑行列总数线性增长。
- 非空单元格数增长时，内存和 SQL 成本有可测量的增长曲线。

## 5. 质量门禁

合并代码前至少执行：
- 前端 lint、单元测试、构建。
- 后端格式/静态分析、单元测试、集成测试。
- 数据库变更验证：备份可恢复、结构与文档一致、关键查询执行计划已检查。
- API 契约测试。
- 按 `frontend/tests/manual/` 完成人工浏览器验收并记录结果；本项目不要求安装或运行 Playwright。
- 关键性能基准的回归检查。

性能阈值应基于稳定基准和容忍区间，不应因单次 CI 噪声频繁失败。
