# 07. 命令、剪贴板、撤销重做与公式

## 1. 命令模型

所有修改通过命令执行，避免 UI 直接修改数据后难以追踪。

建议命令：
- `SET_CELL`
- `SET_CELLS_BATCH`
- `CLEAR_RANGE`
- `SET_CELL_STYLE`
- `SET_RANGE_STYLE`
- `INSERT_ROWS` / `DELETE_ROWS`
- `INSERT_COLUMNS` / `DELETE_COLUMNS`
- `MERGE_CELLS` / `UNMERGE_CELLS`
- `RESIZE_ROW` / `RESIZE_COLUMN`
- `RENAME_WORKSHEET`

每个命令应定义参数、前置条件、变更集、撤销信息、持久化表示和冲突语义。大范围操作不应把所有受影响单元格都复制多份留在内存中；可使用反向操作、快照引用或分块 undo 记录。

## 2. 撤销/重做

- 本地命令栈按用户意图分组，例如输入单元格的连续字符可合并为一次操作。
- 保存与撤销是不同概念：撤销应产生新的变更，不能把数据库 revision 倒退。
- 对批量粘贴，撤销记录需能恢复被覆盖的数据和格式。
- 行列插入/删除会影响大量引用和数据位置，需要专门设计反向操作。
- 未来多人协作时，不能直接把本地撤销栈照搬为全局逆操作；需要定义针对他人后续编辑的行为。

## 3. 剪贴板

建议支持：
- TSV（制表符分隔）作为基本内部格式；
- HTML 表格用于与网页/办公软件交换格式；
- 纯文本作为降级格式；
- 内部 MIME/JSON 格式用于保留样式、合并区域和类型信息（可选）。

需要处理单元格内换行、制表符、引号、空白值、不同系统换行符、超大粘贴和浏览器剪贴板权限。粘贴前先解析并估算范围大小；超出限制时给出确认、异步处理或拒绝。

复制/粘贴的外部内容是不可信输入，必须限制尺寸并避免把文本当作 HTML 执行。导出 CSV 时还要考虑公式注入风险（以 `=`, `+`, `-`, `@` 等开头的文本）。

## 4. 公式引擎策略

建议创建 `FormulaEngine` 适配接口，不让核心模型直接依赖第三方库 API。

```js
export class FormulaEngine {
  setCellInput(sheetId, row, col, input) {}
  getCellValue(sheetId, row, col) {}
  recalculate(changedCells) {}
  dispose() {}
}
```

## 5. HyperFormula 可行性

HyperFormula 值得作为候选方案，但必须在原型阶段验证：
- 许可证是否满足商业用途与分发要求；
- 函数覆盖是否满足产品需求；
- 最大行列配置与内存/耗时表现；
- 大范围 `SUM`、链式依赖、循环引用和批量粘贴的重算成本；
- 与自研稀疏模型之间的同步成本。

不能因为库支持设置较大的 `maxRows` 就认定百万行工作簿可流畅计算。公式引擎通常需要维护依赖图和计算状态；即使网格渲染是虚拟化的，公式计算也可能成为主要内存瓶颈。

## 6. 计算边界

- 首期先实现文本、数字、布尔值、日期等值类型，不要自己手写一个“看起来像 Excel”的公式解析器后就宣称完整兼容。
- 如果首期不支持公式，应明确保存和展示原始公式的行为。
- 公式缓存应可失效和重算。
- 定义错误值（例如 `#REF!`、`#VALUE!`）的内部表示。
- 公式引用、工作表重命名、插入/删除行列和复制填充时的相对/绝对引用规则必须有测试。
- 公式执行不能执行任意 JavaScript；不使用 `eval`。
- 对公式计算设置资源限制和可取消机制，防止复杂公式阻塞 UI。

## 7. 行列结构变更

插入/删除行列不仅是改变行列数，还涉及：
- 单元格坐标迁移；
- 合并区域变更；
- 公式引用重写；
- 命名区域和冻结窗格（若实现）；
- 撤销记录；
- 持久化批量迁移。

首期可以限制为工作表尾部追加行，后续再实现任意位置的结构性变更，降低数据模型复杂度。
